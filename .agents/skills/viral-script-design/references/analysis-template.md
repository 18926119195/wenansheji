# 拆解与生产模板

按交付需要裁剪。多篇输入先逐篇编号，最后再归纳。

## 每篇报告

| 字段 | 写法 |
| --- | --- |
| 受众与场景 | 谁正在遇到什么问题，看到什么线索会判断与自己有关。 |
| 承诺到兑现 | 一句话写开头让人期待什么，及末尾给出的证据、答案或结果。对比标题、首帧、首句与结尾。 |
| 节点地图 | 位置、原稿短片段或画面、它完成的工作、观众此时在等什么、它如何推进下一段。 |
| 主要问题 | 指到具体句子，给出可替换句或可拍动作。标记依据是文本、画面或数据，以及对留存影响的假设。 |
| 可移植机制 | 用「[观众想验证的问题] → [看得见的进展] → [可核对的答案]」这样的变量结构。附定位和最容易失效的条件。 |

无时间戳时用段号或句号编号，篇幅较长时用章节和关键句定位。无需为每句话造标签。多篇时用「机制／支持样稿和位置／例外／可试的新题材」对照，把样本里的高频和实际高表现分别记录。

## 成稿与测试

每条成稿附开场及首帧、分段口播、相应画面和结尾兑现。实验尚未拍摄时，准备有条件的两个结尾。标注需要实测、授权或来源的素材。多个候选使用不同视角、叙事或拍法，挑一个最可执行的先成稿，按用户要求扩展其余。

测试记录保留「稿件编号、单一改动、控制项、目标信号、实测数据、结果解释」。同一个主题的开场对照可以保留正文，只比较最早呈现的线索。平台分发、人群、发布时间或样本大小发生变化时，在解释里注明。中文口播优先朗读并核对实测时长，可读性经验为断句和用词提供参考。
