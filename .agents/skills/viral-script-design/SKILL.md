# 视频文稿拆解与批量改写

按用户给的任务交付拆解、改写或批量成稿。细读原稿和现有标题、画面及数据。只有文案也能拆解，凭文字无法观察的画面和数据标为待核对。平台或时长未给出时，先说清采用的假设并继续。

用 [拆解与生产模板](references/analysis-template.md) 组织深度报告。想核对方法出处时查 [Jenny Hoyos](../../../research/jenny-hoyos.md) 的 Shorts 笔记和 [Aprilynne Alter](../../../research/aprilynne-alter.md) 的长视频笔记。需要看完整迁移时参考 [案例试跑](../../../examples/script-analysis.md)。

## 逐篇拆解

1. 用一句话写出「给哪类人看，开头承诺了什么，结尾交付了什么」。标题或缩略图缺失时，将你推断的点击承诺注明为推断。找出首个有用信息出现的时间或位置。短视频关注首帧与首句让谁停下，长视频另看标题与缩略图的承诺是否在进片后尽快确认。
2. 按观众收到的新信息分段。给每段定位、功能、观众当下的问题、能提供的画面和下段的起因。若调换两个节点仍能读通，检查是否只是并列举例。并列结构适合清单或对比，确保每个节点都有新价值。
3. 为最重要的判断附证据和置信度。把稿件里直接可见的内容、对观众反应的假设、已观测的后台或公开指标区分开。用近似播放口径、时长、发布窗口和频道基线解释异常表现。只有爆款样本时，共性作为创作假设记录。
4. 按影响挑选可改之处。优先检查听不懂的开场、兑现延迟、无新增信息的段落和缺画面证据的断言。提出具体替代句或可拍动作，写明所改变的机制与需要验证的指标。

## 跨稿提取与批量生产

1. 把共性写成含变量的机制卡，并列出适用题材、失效条件和支持它的原稿位置。同一句型只在一篇出现时，可以作为候选创意。若两篇以上表面相似，检查观众留下来的理由是否一致。
2. 先定每条新稿能拍到的证据、约束、结果，再写开场和末句。给同一题材生成不同观看理由的版本，例如先亮结果、提出可实测的对比、从具体误区演示。按要求保留账号语气，换用原创新场景、细节、画面与表达。用时长预算、短句朗读和逐段画面对齐检查成稿。
3. 对实验稿，在拍摄前先写条件和两个可能结果，拍完再填真实结果。引用、数字、体验和成效要有出处或素材。需要用户补材料的地方显式标记，测试草案保留可用部分。
4. 选最值得验证的变化，为批量稿提出小规模对照。测试开场时尽量保留题材、承诺、正文、时长和制作规格，记录发布差异。Shorts 可观察停下观看比例、首段留存和平均观看百分比。长视频可观察展示点击率、前 30 秒留存和首次关键掉点。单次前后变化记为观察。
