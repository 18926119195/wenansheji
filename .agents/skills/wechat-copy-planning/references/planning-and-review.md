# 公众号文案策划与复盘工作表

## 写新稿

| 要定的事 | 可以直接填写的问题 |
| --- | --- |
| 读者与时机 | 谁在什么情境看到？他现在的问题能用一句原话说清吗？有哪些评论、咨询、样本或一手资料支持？ |
| 目标与入口 | 主要想得到转发、理解、有效回应，还是知情报名？从订阅、转发、社群或其他入口来的人，各自已经知道什么？ |
| 文章判断 | 这次真正要说的一件事是什么？最有力的反问是哪一句？什么材料可以回答？ |
| 标题与首屏 | 写出标题、摘要或封面提示、首段和结尾。只看卡片会怎么理解？正文第一处兑现在哪里？ |
| 逐段排布 | 每段填“上一问 → 本段新信息与证据 → 下一问”。删去本段，后面会少哪一个必要步骤？ |
| 收尾与动作 | 哪句话足以复述全文？读完的下一步是什么？为作决定，读者还需要哪项信息？ |

手机预览时，可以请几位接近实际读者的人先只看卡片，复述他们期待的内容，再标记第一处想停或想跳的地方。对招募稿，追加一个任务，让试读者用自己的话复述适合对象、花费、时间、关键要求和入口。误读出现后改一处，再测同一个问题。

冷启动时可以先从一个很窄的主题做三个测试。以“第一次实习的大学生”为例，用一篇帮人辨认机会，一篇拆解简历上的具体问题，一篇讲清何时适合参加练习或带反馈的服务。选题记录里写上真实来源、文稿链接和收到的新问题。根据每篇的实际目标看反馈，用高频追问排下一篇，再把读者自然会连看的内容加上相互入口。

## 拆旧稿

先做一张最短证据表。原文位置要足以让读者找到对应句子。

| 原句或定位 | 可查的文案选择 | 推演的读者反应 | 如何验证 |
| --- | --- | --- | --- |
| 标题、首屏、转段或结尾 | 写出句式、节奏、信息顺序或行动门槛 | 用“可能”解释读者为什么点开、继续、转发或完成动作 | 指出需要的稿件版本、发布记录、后台指标或试读任务 |

篇幅位置可按正文去掉空行、占位图、导出符号和署名后的可见字符粗估。它有助于定位小结论出现得早晚。实际读者的停留位置需要另有阅读证据。

面试叙述先给文章目标，接着讲一个策略决定和两处原文，一句话交代代价和验证方式。当前复盘可以用“我从这版成稿看到”“如果现在重做，我会”。原始草稿、协作记录和带口径的发布数据可以支持更具体的职责和结果陈述。

## 选择指标和比较对象

| 主目标 | 优先证据 | 比较时要固定的口径 |
| --- | --- | --- |
| 广泛传播 | 同窗口阅读人数，分享人数及来源。需要比例时，使用同一稿件同一窗口的去重分享人数和阅读人数 | 同类题材、同账号和接近的发布位置。查看热点、推送及外部转发来源差异 |
| 共鸣或关系 | 分享、有效留言、回复。有原始留言时可抽样编码“表达认同、转述观点、讨论下一步” | 同一时间窗和留言采样方式。把语气反馈与人数分开读 |
| 筛选或转化 | 可归因报名人数、有效报名人数、首项任务完成人数或退款人数，按服务实际流程取数 | 同一批和同一时间窗。入口访问转报名、报名转首项任务分别用各自能追溯的分母 |

按账号和实际周期选择窗口，比如发布后 24 小时与 7 天。招募也可用报名首日和完整招募期，并延伸到约定的首项任务观察日。记录原始人数、统计日期、数据来源与样本量。同目标历史稿能取得时，可用其中位数作参照。没有后台字段或样本时，明确哪个问题仍然没有答案。

把同时改过标题、渠道或发布时间的比较记作观察。条件允许时优先只改一个要验证的因素，保留版本和受众入口，判断这次反馈能否支持下一轮选题或改稿。
